# 관리자 웹 인수인계

운영자는 가입·체결·상환 현황과 처리 이력을 조회한다. 채권자·채무자의 계약 상세, 원문, 영수증은 두 당사자만 열 수 있다. 이 문서는 2026-11-28에 받은 인프라팀의 **바로바로 관리자 페이지 구현 명세 초안**을 최신 [요구사항표](requirements.md)와 대조한 것이다.

## 구현 전에 맞출 범위

| 최신 요구사항 | 인프라 초안과의 관계 | 이슈를 만들 때 정할 것 |
| --- | --- | --- |
| AD-01 관리자 로그인, NFR-13 관리자 권한 | 초안에서 ‘AD-01 운영 대시보드’는 보류로 적혀 있다. 현행 AD-01은 관리자 로그인이다. | 관리자 세션·역할과 401·403 응답을 BE와 합의 |
| AD-02 운영 현황 | 요구사항은 가입 회원 수·진행 중 계약 수·연체 계약 수·실패 거래 건수다. 초안은 기간 내 신규 가입·신규 체결·상환 완료·신규 연체를 제안한다. | PM·BE·FE가 시연 카드, 기준 시각, 집계 단위를 확정. 현재 연체 계약 수와 기간 내 신규 연체 회차 수는 별개 지표 |
| AD-03~06 회원·계약·거래 조회, 지연·실패 확인 | 운영 참조값으로 조회한다. 초안의 서비스 상태 카드는 Gateway·transfer 단위 관측치다. | 업무 조회 화면별 허용 필드와 조회 권한, 시연 범위. 서비스 상태 카드는 선택 연동 |
| AD-07 관리자 활동 기록 | 운영자가 어떤 대상을 조회했는지 남기는 기록이다. 초안의 업무 감사 로그에는 계약 체결·상환 등 업무 이벤트가 담긴다. | 두 로그의 주체·대상·결과와 접근 정책을 구분. 관리자 열람 기록은 서버에 보존 |

초안의 1차 시연 후보는 업무 카드·일별 추이·업무 감사 로그·접근 제어다. 시연 포함 여부와 서비스 상태 카드 연동 시점은 세 팀의 합의 대상이다. 회원·계약 수정, 거래 재실행 버튼은 조회 화면 범위 밖이다.

## 화면과 데이터 계약 초안

아래 세 경로는 협의용 예시다. 실제 호출 전에 Gateway 경로·필드·페이지 방식과 권한을 확인하고 이 표에 계약 링크를 추가한다.

| 영역 | 요청 예시 | 필요한 데이터와 표시 |
| --- | --- | --- |
| 기간 현황·추이 | `GET /api/admin/overview?from=YYYY-MM-DD&to=YYYY-MM-DD` | `signups`, `contractsSigned`, `repaymentsCompleted`, `newOverdue`, `dailySeries`, `updatedAt`. 기간·단위·마지막 갱신 시각 표시 |
| 업무 감사 로그 | `GET /api/admin/audit-events` | 기간·유형·커서. `items`, `nextCursor`, 행의 `occurredAt/action/targetRef/result/actorLabel`. 최신순이며 필터 변경 시 첫 페이지로 이동 |
| 서비스 상태 | `GET /api/admin/service-health` | 서비스별 `service/status/requestCount/errorRatePct/p95LatencyMs/observedAt`. 업무 기간과 별도로 관측 시각 표시 |

업무 기간은 최근 7일을 기본으로 오늘·최근 30일·직접 선택을 제안한다. KST 시작일 00시 이상, 종료일 **다음 날 00시 미만**으로 카드·차트·로그를 일치시킨다. 신규 체결은 고유 계약, 상환 완료와 신규 연체는 고유 회차를 세는 제안이다. 부분 상환·수정 계약·재전달 이벤트의 포함 여부를 BE가 업무 시각 기준으로 정의한다. 작은 화면에는 차트와 같은 날짜별 수치를 텍스트로 제공한다.

## 화면에서 구분해야 할 결과

| 입력 또는 상황 | 기대 화면 |
| --- | --- |
| 첫 조회 / 성공했으나 0건 | 첫 조회는 로딩, 조회된 수가 0이면 카드에 0, 비어 있는 목록에는 안내 |
| 미로그인 401 / 일반 회원 403 | 로그인 안내 / 접근 거부. 이전 관리자의 캐시와 카드 수치가 노출되지 않아야 함 |
| 특정 API만 실패 | 해당 영역에 이유와 재시도. 이미 조회한 다른 영역은 계속 사용 |
| 최근 관측 구간에 요청 0건 | 오류율·p95에 ‘요청 없음’ |
| 미연동 / 관측값 누락·오래됨 | ‘연동 준비 중’ / ‘확인 불가’ 또는 ‘수집 중단’. 0이나 정상으로 대체하지 않음 |

관측 구간은 최근 5분이 제안돼 있다. 상태 임계치·오래된 관측값 판정은 인프라와 합의한다. Prometheus의 `up`은 수집 가능 여부다. 정상·주의·장애는 텍스트로도 구분한다.

## 팀 간 인계와 완료 확인

- **FE**는 React 웹 화면과 Gateway 호출을 담당한다. 가상 응답으로 정상·빈 결과·부분 오류·거부 화면을 만들고, 시연 주소·환경 설정·빌드 방법·재현 순서를 넘긴다.
- **BE**는 Gateway와 admin에서 권한을 확인하고, 허용된 필드만 응답한다. 업무 서비스 API 또는 Kafka 기반 집계를 선택하고 이벤트 중복을 제거한다. FE에 성공·0건·실패 예시와 데이터 갱신 기준을 제공한다.
- **인프라**는 공개 진입점(ALB/WAF)에서 Gateway·admin까지의 경로, 배포 주소와 내부 수집 상태를 확인한다. Prometheus·Grafana는 내부에 두고 서비스 상태 카드에는 admin이 고정 쿼리로 가공한 값만 전달한다. 상세 장애 분석은 권한 있는 담당자가 내부 Grafana·CloudWatch에서 수행한다.

통합 시 가상 계약을 한 건 체결하고 동일 이벤트를 재전달해도 집계가 한 건인지 확인한다. 자정 경계에서 기간을 변경해 카드·추이·로그가 일치하는지 본다. 일반 회원으로 관리자 URL과 API를 각각 열어 접근 거부를 확인하고, 응답 본문에도 연락처·계좌 원문이나 계약서가 없는지 확인한다. 서비스 상태 연동을 선택했다면 요청 0건·수집 중단·조회 장애를 각각 재현한다.
